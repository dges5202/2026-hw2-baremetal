## Project Overview
This project challenges you to develop a simple system using RISC-V assembly language. Throughout the process, you will explore essential low-level programming concepts, such as:
- Efficient use of registers for optimized code execution.
- Writing functions and adhering to RISC-V calling conventions for both internal and external functions.
- Memory management with static data and the stack; the bare-metal playground has no allocator, so supply your own (e.g., a bump allocator) if a program needs one.

## RV32I Feasibility and Optimization Leads
All four programs can run under the RV32I-only rule. The notes below record what each needs and where to look for gains; they are starting points, not the answer. Take the C code in the quiz solutions as the C baseline, write a C version wherever the quiz gives only assembly or fragments, and measure every optimization against that baseline.

Compiling the C fragments of the three quizzes with GCC 15.2.0 (`-march=rv32i_zicsr -mabi=ilp32 -ffreestanding`, at `-O2` and at `-Os`) leaves only `__mulsi3` and `__muldi3` unresolved. No division helper is needed: `/ 128` becomes a shift, and `op3` compiles to the seven instructions listed in Quiz 3. Your own build must still check the undefined symbols (`nm -u`) with your compiler version.

| Program | What RV32I lacks here | Replacement | Where to optimize |
|---|---|---|---|
| minirubik (Homework 1) | Nothing new: Homework 1 already ran on RV32I | Replace Ripes environment calls with `write`/`exit`; fit the 4 KiB stack | Keep the Homework 1 algorithm and budgets as the baseline; compare its tables, packing and search loop under `-O2` and `-Os` against your assembly |
| Quiz 1 Problem B, BFloat16 | `mant_a * mant_b` and `mid * mid` need multiply; a `float` argument must never be used in arithmetic | Your `__mulsi3`; treat binary32 as its `uint32_t` bit pattern (the `float` ABI passes it in integer registers, and `memcpy` between `float` and `uint32_t` needs no F instruction) | Specialize the 8-bit by 8-bit mantissa product as an unrolled shift-and-add with early exit; replace the binary search over [90, 256] (at most 8 iterations, one multiply each) with a digit-by-digit integer square root or an incremental square `(m+1)^2 = m^2 + 2m + 1`, which needs no multiply; test the rounding constant `0x7FFF` and the tie-to-even term across all 65,536 low-half patterns, with both values of bit 16 |
| Quiz 2 Problem A, binary GCD | Nothing: the quiz code is already RV32I with no `mul`, `div` or `rem` | Replace the Ripes environment calls in `main` (numbers 4, 36, 11 and 10) with `write` (64) and `exit` (93), and write an unsigned-to-decimal routine without division (repeated subtraction of powers of ten) | Write the C version from the four identities (it needs no libgcc); the assembly strips factors of two bit by bit in three loops (`pa_both`, `pa_left`, `pa_right`), so replace them with a count-trailing-zeros step (RV32I has no `ctz`: use a de Bruijn table or a binary search), and try a branchless minimum/maximum with `sltu` in place of the `bgeu` swap |
| Quiz 3 Problem C, code parts | `q_mul` forms a 64-bit product, so GCC calls `__muldi3` (which in turn needs `__mulsi3`) | Your 32-bit by 32-bit to 64-bit signed multiply, with the `(1 << (Q - 1))` rounding and the arithmetic shift of a 64-bit value done on a register pair | `op1` and `op2` are bitwise models of `+` and `-` whose loop count depends on the operands; keep them as C references and replace them with `add`/`sub`. Specialize `q_mul` for constant operands (shift-and-add on the set bits), or split into 16-bit partial products; check the tie-rounding of negative products (`q_mul(-3, 524288)`) in your tests. Parts 2 to 4 (adders, a sequential circuit, timing) are not programs and are not ported |
